# つむぐ — 部門ナレッジポータル

社内に散在する説明資料、Wiki、動画、業務手順へのリンクをまとめるポータルサイトのサンプルです。知識を探すことと、教材を順番に学ぶことの両方を支援します。

## 開き方

リポジトリ直下の `index.html` をブラウザで開いてください。ビルド、Node.js、依存ライブラリのインストールは不要です。一般的な静的 Web サーバーにもそのまま配置できます。

## 3つの比較サンプル

[比較ページ `samples.html`](samples.html) を開くと、用途の異なる3つのポータルを試せます。既存の「つむぐ」のサイドバーからも移動できます。

| サンプル | 主な用途 | 試せる操作 |
| --- | --- | --- |
| [PLAYBOOK](src/samples/playbook/index.html) | 業務・手順 | 手順を検索・選択し、作業チェックリストを進める |
| [STEP Academy](src/samples/academy/index.html) | 教育・育成 | 順序付き教材と確認問題で学習を進める |
| [SHELF](src/samples/shelf/index.html) | 資料の探索 | テーマや種類で資料を探し、あとで読むに保存する |

各サンプルの進捗・保存状態は独立しています。既存の「つむぐ」で追加した資料やコースは共有されません。詳しくは [サンプル比較と使い方](docs_from_agent/sample-comparison.md) を参照してください。

## できること

- 資料名・概要・タグのキーワード検索と、カテゴリ・資料種別での絞り込み
- グリッド／リスト表示、更新日・タイトルでの並び替え
- リンクの追加とブックマーク
- 既存の資料リンクを組み合わせた学習コースの作成と、上下ボタンによる学習順序の指定
- ステップごとの本人チェック、または確認問題に正解したときの完了記録

登録したリンク、ブックマーク、学習進捗はブラウザの `localStorage` に保存します。**このサンプルでは他の利用者や端末と共有されません。** ブラウザのデータ削除で保存内容も消えます。保存が利用できない場合は画面内に案内を表示し、その画面を閉じるまでの一時的な操作を継続できます。`file://` での保存の扱いはブラウザに依存するため、継続利用には社内の静的 Web サーバーを推奨します。

## リンクを順番につないで学ぶ

1. 新しい資料や動画は「リンクを追加」で登録します。
2. 「学習コースを作成」でコース名と説明を入力し、資料を順序に追加します。
3. 各資料の上下ボタンで読む・見る順番を変更します。
4. 完了の確認方法を選びます。「確認問題」では各ステップに問題・3つの選択肢・正解を設定します。「読了を自分でチェック」なら問題の設定は不要です。
5. コースを保存して開くと、指定した順番で資料と確認欄が表示されます。

確認問題は誤答時には完了せず、正解したステップだけを完了として保存します。本人チェックは自己申告です。どちらも実際の読了・視聴を自動で証明するものではなく、理解を確認するための補助です。順番は表示上の案内で、前のステップが未完了でも他の資料を開けます。

作成したコースもこのブラウザに保存されます。認証や受講者ごとの集計、管理者承認は未実装です。確認問題の正解はブラウザ内のコースデータに含まれるため、正式な試験や修了証明には利用しないでください。

## 社内資料への差し替え

`src/portal/data.js` の `resources` に資料を、`courses` に学習順序を定義します。コースの `steps` は資料の `id` を順番に指定します。`url: null` の資料は掲載例であり、実際の社内資料には遷移しません。公開参考資料と利用者が追加したリンクは区別して表示します。

### JSONを編集して画面に反映する

メインポータル「つむぐ」のサイドバーにある「データの入出力」（モバイルでは上部の「データ入出力」）を使います。

1. 「JSONを出力」で、現在のカテゴリ・資料リンク・学習コースを `portal-catalog.json` に保存します。
2. テキストエディタでJSONを編集します。資料のタイトル・URL・タグなどや、コースの `steps` の並び順を変更できます。
3. 「編集したJSONを読み込む」でファイルを選び、件数と検証結果を確認します。
4. 「この内容で置き換える」を押すと、一覧全体を置き換えてHTMLの表示に反映します。読み込みだけでは変更されません。

取り込みは追加方式ではありません。置き換え前にJSONを出力してバックアップしてください。JSONの形式、不正なURL、ID重複、存在しない資料を参照するコースなどは検証で拒否します。最大ファイルサイズは2MBです。現状はJSONに対応し、YAMLの読み込みやファイル変更の自動監視は行いません。

JSONの出力には個人のブックマーク・学習進捗を含みません。確認問題の問題文と正解はコース情報として含みます。取り込み後は、存在する資料のブックマークを維持し、コースと参照する資料の内容がすべて同じ場合だけ進捗を維持します。教材のURL・本文・確認問題などが変わったコースの進捗は解除されます。

### ほかの利用者にも配布する

取り込んだデータはこのブラウザに保存され、配置ファイルより優先されます。ほかのブラウザや利用者には自動共有されません。「配布用 data.js を出力」でダウンロードし、プロジェクトの `src/portal/data.js` を手動で置き換えて配布してください。**配置ファイルを置き換えた後は、`index.html` を再読み込みするか開き直してください。** 配置データはページを開いたときに読み込まれます。ブラウザがプロジェクトのファイルを直接書き換えることはありません。生成ファイルは通常のJavaScriptとして読み込むため、`index.html` を直接開く利用方法にも対応します。

以前取り込んだブラウザでは、ページを再読み込みしてから「配置ファイルの内容を確認する」→「この内容で置き換える」でブラウザ内の優先データと追加資料・コースを取り除き、配置した `data.js` の内容へ戻せます。戻す前に必要な追加内容をJSONへ出力してください。3つの比較サンプルの独立した保存状態は、この入出力の対象外です。

変更前後の教材を比較して進捗を解除するのは、JSONの読み込み・適用、または配置データへの復帰を行ったときです。`data.js` を直接置き換えて再読み込みするだけの場合、従来のIDだけで保存された進捗から変更前の教材を判定できないため、自動解除は保証されません。教材の変更に応じて進捗を管理したい場合は、JSONの読み込み・適用を使ってください。

実運用で部門全員が登録内容を共有する場合は、認証、アクセス管理、サーバーでの保存、編集・削除と管理者の運用を追加してください。現在の構成にアクセス制御はありません。実行時に外部フォントや外部 API を読み込みません。登録リンクは利用者が開いたときに遷移します。

調査と構成の説明は [実装メモ](docs_from_agent/implementation.md)、検証方法は [tests/README.md](tests/README.md) を参照してください。
