# 部門ナレッジポータル「つむぐ」実装メモ

## 調査と採用した構成

2026-11-07 に部門の知識共有に利用できる事例を検索し、次の公式ガイドを参考にしました。製品の機能をそのまま再現するのでなく、このプロジェクトの目的に必要な入口を実装しています。

- [Atlassian: Using Confluence as an internal knowledge base](https://www.atlassian.com/software/confluence/resources/guides/best-practices/knowledge-base): カテゴリ・ラベルと検索を組み合わせ、必要な資料に到達しやすくする構成。
- [Atlassian: Knowledge management best practices](https://www.atlassian.com/software/confluence/resources/guides/best-practices/knowledge-management): 部門の入口をまとめ、オンボーディングや業務資料にアクセスしやすくする考え方。
- [Notion: Onboarding guides](https://www.notion.com/help/guides/category/onboarding): チームへの参加と学習を支援するガイド群。

本実装では「すべての資料」「業務の手順」「学習コース」の入口を分けています。学習コースは既存の資料 ID を順序付きで参照し、資料種別が異なっていても同じ順番で学べる構造です。

## コース作成と完了の確認

「学習コースを作成」で登録済み資料を追加し、上下ボタンで読む・見る順序を指定できます。不要な資料は保存前に削除できます。新しく追加したリンクも同じ選択肢に含まれます。サンプル資料はリンク未設定と明示します。作成済みコースの編集・削除は今回の対象外です。

確認方法は「本人チェック」と「確認問題」の2種類です。本人チェックは従来のサンプルコースと同様に自己申告で完了を記録します。確認問題では各ステップに問題、異なる3つの選択肢、正解を設定し、正解したステップだけを完了として保存します。誤答や未回答では完了しません。確認問題モードに本人チェック欄は表示しません。学習順序は案内として示し、資料を開く順番そのものは制限しません。

`tsumugu-v1` に `courses` を追加し、既存の資料・ブックマーク・進捗は維持します。コース ID の衝突、重複ステップ、未知の資料 ID、不正な問題・正解番号は登録・復元時に拒否します。資料とコースの復元後に、両方のコースに対する進捗を復元します。

読了・視聴を自動で証明する機能ではありません。確認問題と正解はブラウザ内に保存されるため、理解の振り返りを補助する用途です。本人認証、受講者別集計、管理者承認、正式な試験・修了証明には別途サーバー側の仕組みが必要です。

## 画面と機能

濃い青緑のサイドバー、明るいグレーの作業面、資料種別ごとの控えめな色を採用しました。学習カードの番号付きルートは、実際のコース内の学習順序を表しています。日本語を中心に、外部フォントなしのシステムフォントで構成しています。

検索はタイトル・概要・タグ・担当の文字列を対象に、全角半角を正規化して複数語の AND 条件で照合します。カテゴリ・資料種別・ブックマークの絞り込みと組み合わせられます。追加したリンクは全資料と同じように検索できます。

利用者入力は DOM の `textContent` とテキストノードで表示します。URL は http / https のみを許可し、ユーザー名・パスワード入りの URL は登録できません。外部リンクは別タブで開き、`noopener noreferrer` を設定します。保存データを復元するときにもリンク情報を検証します。

## データと制約

### JSONによる一覧の編集

メインポータルの「データの入出力」から、カテゴリ・資料・学習コースをJSONに出力し、編集したJSONをファイル選択で読み込めます。個人のブックマークと進捗は出力しません。`catalog.js` の検証結果をプレビューし、「この内容で置き換える」の操作で一覧全体を置き換えます。読み込み失敗やキャンセルでは表示中のデータを変更しません。非同期のファイル選択を連続しても、最後の選択だけを適用可能にします。2MBを超えるファイルは読み込まず拒否します。

適用したカタログは `tsumugu-v1` の `catalog` に保存し、起動時に配置ファイルより優先して復元します。追加資料・コースは復元済みカタログと重複しないように処理します。不正な保存カタログは採用せず、配置ファイルを使い、画面内に案内を表示します。空の資料・コース一覧にも対応し、固定のコースIDを前提にしません。

ブックマークは取り込み後に存在する資料IDだけ残します。進捗はコース定義と参照資料が旧データとすべて一致したときだけ残します。問題、正解、資料URLなどが変更されたコースの古い完了状態を引き継ぎません。

「配布用 data.js を出力」はカタログを通常のスクリプトに変換してダウンロードします。利用者が `src/portal/data.js` を手動で置き換えると、ほかの利用者にも同じ内容を配布できます。HTMLやプロジェクト内のファイルを自動で上書きしません。配置データはページ起動時のスナップショットなので、ファイルを置き換えたらページを再読み込みするか開き直してください。その後、ブラウザ内の優先カタログが残っている場合は「配置ファイルの内容を確認する」から明示的に戻す必要があります。この操作は追加資料・追加コースも取り除くため、事前のJSONバックアップを案内しています。

変更前後の比較による進捗の引き継ぎ判定は、JSON適用または配置データへの復帰の操作時に行います。`data.js` の直接置き換えとページ再読み込みだけでは、従来のIDだけで保存された進捗から変更前の教材定義を復元できず、変更時の進捗自動解除は保証できません。教材変更に応じた進捗管理にはJSON読み込み・適用を推奨します。

対応形式はJSONです。YAML、自動ファイル監視、共有サーバーへの保存は実装していません。3つの比較サンプルは今回の入出力の対象外です。

初期データはサンプル 11 件と公開参考資料 1 件、学習コース 3 件です。未設定の社内 URL は存在するように見せず、紹介ダイアログに「サンプル・リンク未設定」を表示します。実際の社内資料やユーザー情報は含めていません。

ブラウザ内保存キーは `tsumugu-v1` です。認証・全員共有のデータベース・アクセス制御は含みません。保存失敗時はメモリ上で動作し、画面内の案内で知らせます。社内での本運用には、データ共有と権限管理を追加する必要があります。
