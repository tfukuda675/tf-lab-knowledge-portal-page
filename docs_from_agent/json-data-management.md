# JSONで資料・カテゴリ・学習コースを編集する

「つむぐ」の「データの入出力」から、資料リンク・カテゴリ・学習コースをJSONに出力し、編集したJSONを画面に反映できます。ビルドやサーバーは不要です。今回はJSONに対応し、YAMLは対応していません。

## 基本の流れ

1. 「データの入出力」を開き、「JSONを出力」で現在の一覧を保存します。最初のバックアップを残してください。
2. 保存した `portal-catalog.json` をテキストエディタで編集します。形式の参考として `src/portal/catalog.example.json` も用意しています。
3. 同じ画面で編集したJSONファイルを選択します。ファイルの上限は2MBです。
4. 検証結果とカテゴリ・資料・コースの件数を確認します。エラーの場合は元の画面の内容を変更しません。
5. 「この内容で置き換える」で反映します。追加方式ではなく、**一覧全体を置き換えます**。

JSONの変更はその場でHTMLの表示に反映され、再読み込み後もこのブラウザで維持されます。ブラウザは元のHTMLや `data.js` を直接上書きしません。ファイル選択による明示的な読み込みを使い、外部APIやファイルの自動取得は行いません。

出力に含むのはカテゴリ・資料・コースの定義です。個人のブックマークと学習進捗は含みません。JSON取り込みや「配置ファイルの内容を確認する」で置き換えを適用するときは、存在する資料のブックマークを維持し、置き換え前後でコースとその参照資料の定義が変わっていない場合に限って進捗を引き継ぎます。教材URL・説明・問題・順序などが変わったコースの進捗は解除されます。この比較処理は、配布用ファイルの手動配置とページ再読み込みだけでは実行されません。

## 編集例

次のJSONは、カテゴリ1件、資料1件、本人チェック式コース1件を定義する例です。`steps` 内の資料IDの順番が、読む・見る順序になります。

```json
{
  "schemaVersion": 1,
  "categories": [
    {
      "id": "team",
      "name": "部門の基本",
      "icon": "book",
      "color": "teal",
      "description": "最初に確認する資料"
    }
  ],
  "resources": [
    {
      "id": "handbook",
      "title": "部門ハンドブック",
      "description": "体制と仕事の進め方を確認します。",
      "category": "team",
      "type": "Wiki",
      "tags": ["入門", "チーム"],
      "updated": "2026-11-07",
      "owner": "部門運営",
      "url": null
    }
  ],
  "courses": [
    {
      "id": "welcome",
      "title": "最初に読むコース",
      "description": "部門の基本を確認します。",
      "label": "新しく参加した方へ",
      "duration": "自分のペースで",
      "color": "teal",
      "icon": "book",
      "steps": ["handbook"],
      "confirmation": "self",
      "checks": {}
    }
  ]
}
```

`url` の `null` は「サンプル・リンク未設定」です。実際のURLを使う場合は `"https://…"` または `"http://…"` にします。相対URL、ほかのプロトコル、ユーザー名・パスワードを含むURLは登録できません。

## カテゴリの追加・名前変更・削除

- 追加：`categories` に新しい `id` と `name` を持つ項目を追加し、資料の `category` からそのIDを参照します。
- 名前変更：`name` を変更します。`id` が同じなら、資料側の参照を変更する必要はありません。
- 削除：そのカテゴリに属するすべての資料を別のカテゴリIDへ変更するか、資料自体をJSONから削除します。削除資料を参照するコースの `steps` と確認問題も更新してください。

存在しないカテゴリや資料を参照したJSONは取り込めません。カテゴリは最低1件必要です。資料とコースは0件でも構いません。

## 確認問題をJSONで設定する

コースの `confirmation` を `"quiz"` にし、教材IDごとに `checks` を指定します。問題がない教材を含むコースは取り込めません。

```json
{
  "confirmation": "quiz",
  "checks": {
    "handbook": {
      "question": "この資料で確認することは何ですか？",
      "options": ["部門の体制と仕事の進め方", "来月の天気", "個人の買い物履歴"],
      "answer": 0
    }
  }
}
```

`answer` は選択肢の位置で、最初が `0`、2番目が `1`、3番目が `2` です。選択肢は重複しない3つの文字列にします。本人チェック方式は `"confirmation": "self"` です。確認問題は理解度を振り返る補助であり、読了・視聴の事実を自動で証明するものではありません。

## 形式と上限

| 項目 | 形式・上限 |
| --- | --- |
| `schemaVersion` | `1`。省略時も1として扱います |
| `categories` | 1～50件。`id`、`name`は必須。説明は300文字以内。`icon`省略時は`book`、`color`省略時は`teal` |
| `resources` | 0～5,000件。上の例の全項目が必要です。説明・担当は空文字可、タグは空配列可 |
| `courses` | 0～500件。`id`・`title`・`description`・`steps`が必要です。説明は空文字可 |
| ID | 半角英数字・`_`・`-`で1～100文字。同じ種類の一覧内で一意にします |
| 資料名・コース名・カテゴリ名 | 1～100文字 |
| 資料・コースの説明 | 300文字以内 |
| `tags` | 10件以内、各タグは1～30文字 |
| `owner` | 100文字以内 |
| `updated` | 実在する日付を`YYYY-MM-DD`で指定 |
| 資料の`type` | `Wiki`・`資料`・`動画`・`Web`・`手順書` |
| `color` | `teal`・`blue`・`violet`・`orange` |
| `icon` | `home`・`grid`・`list`・`clipboard`・`book`・`bookmark`・`compass`・`code`・`video`・`file`・`globe`・`arrow` |
| コースの`steps` | 実在する資料IDを1件以上、重複せずに学習順で指定 |
| コースの表示項目 | `label`・`duration`は100文字以内。省略時は「学習コース」「自分のペースで」 |
| 確認問題 | 問題は1～300文字、選択肢は各1～200文字、正解は整数0～2 |

カテゴリIDの `all` は絞り込みの予約値です。`__proto__`、`constructor` などJavaScriptの予約済みオブジェクト項目名も、IDやJSONの項目名として使えません。定義にない通常の項目は取り込み時に除外されます。

## ほかの利用者へ配布する

ブラウザで取り込んだ一覧をほかの利用者にも表示したい場合は、「配布用 data.js を出力」を使い、出力したファイルをリポジトリの `src/portal/data.js` に手動で配置してください。JSONやJavaScriptの文字列を実行コードとして連結せず、安全なJSONデータとして生成します。

配置したファイルは、初期データを読み込む「つむぐ」とSHELFへ反映されます。STEP Academyでは共通資料の参照部分に反映しますが、学習内容・確認問題はサンプル独自の固定定義です。PLAYBOOKの手順も独自の固定定義なので、JSONの変更では更新されません。

`data.js` を手動で置き換えたら、まずページを再読み込みしてください。配置ファイルの内容はページ起動時に読み込まれるため、開いたままでは新しいファイルへ切り替わりません。

「つむぐ」ですでにJSONを取り込んだブラウザは、その保存データを配置ファイルより優先します。ページを再読み込みした後、「配置ファイルの内容を確認する」を選び、確認後に「この内容で置き換える」を押します。この操作では、そのブラウザで追加した資料・コースも取り除きます。

ファイルの配布は個人の保存状態を移行したり、変更前後の教材定義を再比較したりする処理ではありません。JSON取り込み済みの上書きデータがないブラウザで `data.js` だけを置き換えて再読み込みすると、同じIDの進捗が残る場合があります。教材変更に応じた進捗解除が必要な場合は、変更前の一覧を表示している画面から編集後のJSONを取り込み、「この内容で置き換える」で反映してください。

認証や部門全員の保存データ同期は含みません。配布用ファイルの配置や共有サーバーの更新は自動では行いません。

## 実装と検証

`src/portal/catalog.js` がJSONの検証・正規化、配布用スクリプト生成、変更のない教材だけの進捗引継ぎを担当します。検証は取り込みと配布用出力の両方で実行し、エラーは最大30件表示します。

Chromeで次の検証を実施しました。

- `tests/catalog-test.html`：52項目すべて成功。ID・参照・URL・日付・確認問題の検証、正規化、安全な配布用スクリプト生成、変更に応じた進捗引継ぎを確認しました。
- `tests/catalog-flow.html`：25項目すべて成功。実際のFileReaderを使い、JSON・data.jsの出力、不正・危険・上限超過ファイルの拒否、プレビュー時の非変更、キャンセルと再表示、カテゴリ・資料名・URL・順序の反映、進捗の維持・解除、再読み込み、追加リンク、配置ファイルへの復元を確認しました。
- 既存機能の回帰確認：`tests/browser-smoke.html` の21項目と `tests/course-flow.html` の20項目が成功しました。
- 390px幅でデータ入出力ダイアログの画像を確認しました。JavaScript構文検査と `git diff --check` は成功し、最終レビュー結果は APPROVE でした。

サイトの利用にブラウザ検証用の自動操作環境や補助スクリプトは必要ありません。JSONの読み込み・出力は通常のブラウザだけで利用できます。
